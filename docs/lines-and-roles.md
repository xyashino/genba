# Lines, Roles, and Forge Andon

Target repos own `.genba/config.json`, `.genba/lines/<name>.yml` and `.genba/roles/<name>.md`. `genba init` writes them from templates embedded in the binary (`with { type: 'text' }`); it keeps existing files unless `--force`. Runtime reads only the repo copies, from the repo root, not order worktrees. No built-in fallback. `genba doctor` parses every line and the roles they use.

## Repo Manifest (`.genba/config.json`)

Auto-generated by `genba init` from stack files, CI config, installed CLIs, and `origin` URL:

```json
{
  "project": "payments-api",
  "rules": "./.agents/rules",
  "skills": "./.agents/skills",
  "herdr": false,
  "git": { "provider": "github", "baseBranch": "main" }
}
```

## Template Lines

| Line | Stations | Use Case |
| :--- | :--- | :--- |
| `fast` | `build -> quality-gate -> deliver` | Chores, docs, small fixes |
| `standard` | `build -> quality-gate -> audit -> deliver` | Most bugs and scoped tasks |
| `feature` | `plan -> build -> quality-gate -> audit -> deliver` | Multi-file features |

## Line Format

Follows `software-factory` lines; `changeover` replaces its `workspace`.

```yaml
name: standard
description: Build behind quality gate, then audit
changeover:
  root: { timeout: 2m, exec: [git fetch origin] }
  worktree: { timeout: 10m, exec: [bun install --frozen-lockfile] }
operators:
  builder: { profile: builder, runner: claude, model: haiku, timeout: 60m, permission: write }
mechanic: { profile: mechanic, runner: claude, model: sonnet, timeout: 20m, permission: read }
stations:
  - { id: build, kind: operator, operator: builder }
  - { id: quality-gate, kind: inspection, timeout: 30m, exec: [bun run ci:verify], onFail: { retry: build, max: 3 } }
deliver: { commit: build.commit, report: build.report, to: new-pr, requireAdr: false }
```

- `changeover.root`: main checkout, before a worktree is created; one at a time across Cells; failure creates no worktree. Genba never cleans or resets the root; commands there must not touch uncommitted work.
- `changeover.worktree`: once per worktree, before its first station. If the worktree was clean, tracked and untracked changes it leaves are discarded.
- Both rerun after a recreated worktree or a failure. Mechanic and escalation skip them.
- Worktrees start from `origin/<base>` when it exists, else local `<base>`.
- `profile` names `.genba/roles/<profile>.md`. Profile `doctor` reports a verdict.
- `permission: read` needs a runner with a read mode. `model` omitted: CLI default.
- `herdr: true` in `config.json` runs every agent interactively in a herdr tab named `<order>:<station>` in its Cell's workspace; hooks and gates stay headless. The agent is stopped when its station ends; its tab stays until the Cell's next agent starts, and its last screen is saved to `step.log`. Needs a running herdr server. Genba does not edit runner trust settings: answer any trust prompt in the pane. Default `false`: headless. Lines have no `headless` key.
- Unknown keys are rejected.
- `timeout`: `s`, `m`, `h`; default `30m`.
- `requireAdr`: delivery needs exactly one new `decisions/` file.
- `init` fills `changeover.worktree` and gate `exec` from the detected stack; `changeover.root` only with an `origin`.

## Universal `ROLE.md` Contract (`stage: runtime`)

Roles (`planner`, `builder`, `doctor`, `mechanic`) compile through `@repo/prompt` with typed frontmatter enforced live by the Cell when the agent calls `genba operator done`:

```markdown
---
id: builder
stage: runtime
rules: [coding, testing]
skills: [evidence]
input:
  order: string
  checks: string
  feedback: string
  lessons: string
  operatorCommand: string
outputs:
  report: { file: report.md }
  commit: { file: commit.txt, format: conventional }
guards:
  requireDiff: true
---
```

- **Rules and skills**: a `rules` entry -> folder `<config.rules>/<entry>` (every file under it, nested too, dotfiles skipped) or file `<entry>` / `<entry>.md`; `skills` -> `<config.skills>/<name>/SKILL.md`; folders default to `.agents/rules` and `.agents/skills`, must be inside the repo. `init` writes the defaults. Genba adds both lists to the prompt as files to read, for every role; no file text is inlined. A listed file missing from the worktree is an environment error. No `rules`: the prompt names the instruction files present (`AGENTS.md`, `CLAUDE.md`, ...). Reading is not enforced; quality gates enforce checks. `init` lists only files the repo has.
- **Guards**: both optional. `forbidPaths` globs match changed files git reports, so not `.git/` or ignored files.
- **Live gatekeeping**: failed output/guard checks return non-zero to `genba operator done` so the live agent fixes them in-session.
- **Runner quirks stay in adapters**: CLI-specific rules live in `adapters/runners/*.ts`, never in `ROLE.md`. Each adapter maps its CLI to one common API (`buildCommand`, `buildHeadlessCommand`, `parseOutput`).
- **Repo memory**: optional `.genba/lessons/<role>.md` injects recurring repo-specific fixes into context.

## Orders, Retries, Incidents

- Checkpoint: each passed write station becomes a commit; push only at delivery or escalation.
- Failed station goes back to `onFail.retry` until its `onFail.max` attempts are used; without `onFail`, operator gets 2 attempts, inspection 1. Retries keep the same model.
- Retries exhausted: one Mechanic run per order, then supervisor. `blocked` and environment errors go straight to supervisor.
- Resolutions: `retry_step` (one more attempt), `restart_from_step`, `restart_from_scratch` (new branch from base), `escalate`, `cancel`.
- `restart_from_scratch` overwrites remote branch only while it still holds what genba pushed.
- Child order waits for parent delivery, then stacks on parent branch until merged.

## Cells, Logs, Workspaces

- Cells are named by slot: `cell-1` .. `cell-N`. Scale down removes the highest names; a running job goes back to the queue without spending an attempt.
- Per Cell: timeline `.genba-local/cells/<cell>/events.jsonl`, process log `.genba-local/logs/<cell>.log`, and with `herdr: true` a workspace `genba:<project>-<repo hash>:<cell>`.
- All three live as long as the Cell. A new Cell starts fresh; `scale` down and `stop` remove them.
- Crash: the replacement gets a new workspace and keeps the old timeline in `crash.jsonl` until the Cell is scaled away or `genba stop`. After a daemon crash, logs stay through recovery.
- Genba records the workspaces it creates (`.genba-local/herdr-workspaces.json`) and closes only those. A same-named workspace it did not create stops Cell setup with an error.
- First tab `logs` runs `genba watch --full --cell <cell>`.
- `genba watch --full [--cell <name>] [--order <slug>]`: header, saved entries of existing Cells, then live; no daemon needed; Ctrl+C ends it. History of removed Cells is gone. Plain `genba watch` streams live daemon events.
- Attempt files: `.genba-local/runs/<order id>/<station>/<job id>/` (prompt, `step.log`, outputs, gate and worktree hook logs), written when the job reports; kept after worktree and Cell removal. A job stopped or crashed midway is not copied. No retention limit: delete the folder to clean up. May hold secrets that agents or commands print.

## Operator Verbs

| Role | Verbs |
| :--- | :--- |
| `builder`, `planner` | `done [--summary]`, `block <reason>` |
| `doctor` | `verdict pass\|fail [--feedback]`, `block <reason>` |
| `mechanic` | `incident <resolution> [--step] [--diagnosis]`, `block <reason>` |
| all | `context`, `read` |

Omitted `--feedback` / `--diagnosis` comes from `audit.md` / `diagnosis.md`. Exit codes: 0 accepted, 1 refused, 2 usage, 3 unreachable.

## Forge-Native Delivery & Andon (`ForgePort`)

| Outcome | Forge Action (`gh` / `glab`) | Local / Hub Record |
| :--- | :--- | :--- |
| **Delivered** | Push branch, open/update PR/MR with proof + retry table | Save `prUrl`, `prNumber`, job runner / model / duration; merge sync in Phase 4 |
| **Escalated (Andon)** | Push WIP branch, open Draft PR/MR + `genba:andon` Issue with Mechanic diagnosis | Save `issueUrl`, `draftPrUrl`; free Cell immediately |
